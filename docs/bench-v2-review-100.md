# Bank-Onto-Bench v2 — 표본 100문항 검수 기록

- 검수일: 2026-08-17 / 검수 주체: 저장소 관리자 세션 (Claude Code 보조)
- 표본: 템플릿별 층화 10% (20개 템플릿, 101문항). 표본 추출은 문항 id의
  CRC32 순으로 결정적 — 재현 가능.
- 방법: 전 표본 문면 정독 + 정답·근거 좌표 대조. 발견 즉시 생성기 수정 후
  전체 재생성 (표본만 고치는 것이 아니라 규칙을 고침).

## 발견 및 조치 내역

| # | 발견 (표본 예) | 원인 | 조치 |
|---|---|---|---|
| 1 | 정의문이 괄호 중간에서 절단 (REG-0848 "…출자지분(투자신탁의 경우에는 수익권") | 정의 조문의 중첩 "…를 말한다" 패턴 | 괄호 균형 검사 필터 추가 — 불균형 정의 제외 (현재 0건) |
| 2 | 조사 오류 "…채권”는 무슨 용어의…" (REG-0850) | 변형 문안이 받침 무시 | 해당 변형을 조사 중립 문구로 재작성 |
| 3 | 조사 오류 "벌금은(는) 최대 얼마" (REG-0911) | 변형 문안의 병기 하드코딩 | 받침 판별 조사 헬퍼 적용 (벌금은/과태료는) |
| 4 | '과(와)' 병기 남용 (compare 템플릿) | 조사 헬퍼 미적용 | 받침 판별 적용. 상품명이 숫자·괄호로 끝나 판별 불가한 경우만 표준 병기 유지 |

## 검수 중 확인한 정상 동작 (오탐 아님)

- `KB 특★한 적금`의 "1개월 만기" 문항: 해당 상품이 12개월 옵션 없이 1개월
  옵션만 공시 — 데이터 충실 반영이며 질문에 만기가 명시되므로 정합.
- 상품명 끝이 괄호·숫자·라틴 문자인 경우의 "과(와)"/"은(는)" 병기: 받침
  판별이 정의되지 않는 경우의 표준 표기.
- 비교형(compare) 질문에 두 상품명이 모두 등장하고 정답이 그중 하나인 것:
  이지선다를 문면에 명시하는 closed-choice 설계 (단리/복리와 동일).

## 전수 기계 검수 결과 (표본 아님, 1,000문항 전체)

- 정답 문자열의 질문 노출(closed-choice 제외): **0건**
- 질문 내 개행·HTML 엔티티·태그: **0건**
- 질문 중복: **0건** / id 중복: **0건**
- boolean 균형: YES 162 / NO 150
- `datasets.load_dataset` 왕복: 통과 (전 필드 string, unit 항상 존재)
